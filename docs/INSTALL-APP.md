# הפעלת אפליקציית המובייל

האפליקציה בנויה ב-Expo (React Native) ומושכת את המוצרים, הקטגוריות, המלאי
והמחירים ישירות מהחנות דרך Shopify Storefront API. אין בסיס נתונים נפרד ואין
מה לתחזק - כל שינוי בחנות מופיע באפליקציה מיד.

התשלום מתבצע ב-Checkout של שופיפיי עצמו, כך שכל אמצעי התשלום שמוגדרים בחנות
עובדים גם באפליקציה.

---

## שלב 1 - יצירת טוקן Storefront API

> **תוקן.** הגרסה הקודמת של המסמך הזה הפנתה ל**הגדרות → אפליקציות וערוצי מכירה →
> פיתוח אפליקציות**, ומשם ללשונית **API credentials** שהציגה את הטוקן.
> **המסלול הזה לא קיים יותר.** התיעוד של שופיפיי קובע: *"You can no longer create
> new custom apps in the Shopify admin"*, ו*"as of January 1, 2026, you can no
> longer create new legacy custom apps"*. אפליקציות שנוצרו כך בעבר ממשיכות לעבוד,
> אבל אי אפשר ליצור חדשות.
>
> אפליקציה שנוצרת ב-**Dev Dashboard** גם היא לא פותרת את זה: היא לא מציגה את
> הטוקן בשום מסך בממשק הניהול, כי שופיפיי מצפה שהאפליקציה תשלוף אותו בעצמה
> ב-OAuth או במוטציה `storefrontAccessTokenCreate` מול ה-Admin API.

**המסלול הנכון היום: ערוץ Headless.** שופיפיי כותבת במפורש שערוץ זה **מייצר את
הטוקנים בשבילכם ומציג אותם בממשק** - בלי קוד, בלי CLI, בלי לגעת ב-API secret.

1. **הגדרות → אפליקציות וערוצי מכירה → Shopify App Store** → להתקין את
   **Headless**
2. ליצור **custom storefront** חדש
3. במסך הטוקנים יופיעו **שני** טוקנים. לקחת את זה שמסומן
   **Public access token**

### ⚠️ שני דברים שחייבים לקרות אחרי ההתקנה

**1. לפרסם את הקטלוג לערוץ החדש.** ערוץ Headless יוצר **publication** חדשה.
נבדק מול החנות: **לכל חמש ה-publications הקיימות `autoPublish: false`**, כלומר
מוצרים **לא** מתפרסמים אוטומטית לערוץ חדש. בלי השלב הזה ה-API יחזיר 200 עם **אפס
מוצרים**, וזה נראה בדיוק כמו טוקן שגוי.

> מוצרים → לסמן הכל → **פעולות בכמות** → הוספת ערוץ מכירה → Headless.
> לחזור על אותו דבר לקטגוריות.

**2. לא לבלבל בין שני הטוקנים.**

| טוקן | סודי? | לאפליקציה? |
|---|---|---|
| **Public access token** | לא. ציבורי בהגדרתו, נועד לצד לקוח | ✅ **זה מה שנכנס ל-config** |
| **Private access token** | **כן. סודי** | ❌ אסור בבנדל של האפליקציה |

ה-Private token מיועד לשרת בלבד. הוא יושב על אותו מסך בדיוק, ולכן קל להעתיק את
הלא-נכון. **האפליקציה היא צד לקוח - היא תמיד מקבלת את ה-Public.**

## שלב 2 - הדבקת הטוקן

פותחים את `mobile-app/src/config.ts` ומדביקים:

```ts
storefrontAccessToken: 'המקום-שבו-מדביקים-את-הטוקן',
```

הדומיין כבר מוגדר נכון:

```ts
storeDomain: '3007b3-4.myshopify.com',
```

זה הדומיין הפנימי של החנות בשופיפיי - **לא** `anshilo.com`. אין צורך לשנות אותו.

שאר הפרטים בקובץ (טלפון, וואטסאפ, כתובת, שעות) כבר מלאים בערכים האמיתיים, ומשם
הם מוזרמים לכל המסכים.

## שלב 3 - הרצה על הטלפון

```bash
cd mobile-app
npm install
npx expo start
```

מתקינים **Expo Go** מה-App Store או מ-Google Play וסורקים את ה-QR. באנדרואיד
סורקים **מתוך** Expo Go; באייפון סורקים עם **אפליקציית המצלמה**, שמציעה לפתוח
ב-Expo Go. כל שינוי בקוד מתעדכן במסך תוך שנייה.

לבדיקה שהכל מתקמפל:

```bash
npx tsc --noEmit
```

### ⚠️ שני דברים לדעת לפני שמסיקים שמשהו שבור

**1. הקוד לא נמצא בברנץ' ברירת המחדל.** הברנץ' של העבודה הוא
`claude/shopify-store-modern-design-746p2i`. מי שמוריד ZIP מגיטהאב בלי להחליף
ברנץ' קודם - יקבל קוד אחר. בדף הריפו: בורר הברנצ'ים → לבחור את הברנץ' → ואז
**Code → Download ZIP**.

**2. ב-Expo Go העברית תיראה משמאל לימין. זה לא באג.**

`app.json` מגדיר `forcesRTL: true` דרך התוסף `expo-localization`. נבדק בקוד
התוסף עצמו: הוא כותב `ExpoLocalization_forcesRTL` ל-`Info.plist` באייפון
ול-`strings.xml` באנדרואיד - כלומר **ערכים נייטיביים שנקבעים בזמן בנייה**.
חיפוש אחר `forcesRTL` בקוד הריצה של החבילה לא מחזיר כלום.

Expo Go הוא בינארי מוכן שאפל וגוגל בנו מראש, וה-`Info.plist` שלו הוא של Expo -
לא שלנו. **לכן ההגדרה לא חלה שם**, והפריסה תיראה LTR.

| מה רוצים לבדוק | במה להריץ |
|---|---|
| שהנתונים זורמים - מוצרים, מחירים, מלאי, עגלה | **Expo Go** מספיק |
| **איך זה נראה** - פריסה, RTL, יישור | **חייבים build אמיתי** |

ל-build אמיתי באנדרואיד, שמייצר APK להתקנה:

```bash
npm install -g eas-cli
eas login                                          # חשבון Expo חינמי
eas build --platform android --profile preview      # הפרופיל כבר מוגדר ב-eas.json
```

הבנייה רצה בענן של Expo ולוקחת בסדר גודל של 10-20 דקות. בסוף מתקבל קישור
להורדת APK, שאפשר להתקין ישירות על מכשיר אנדרואיד ואפילו לשלוח למישהו אחר.
באייפון אין דרך מקבילה בלי חשבון Apple Developer.

## שלב 4 - העלאה ל-App Store ול-Google Play

זה שלב נפרד שדורש חשבונות מפתח בתשלום. מה שצריך:

| דרישה | עלות | הערות |
|---|---|---|
| Apple Developer Program | 99$ לשנה | חובה ל-iOS |
| Google Play Developer | 25$ חד-פעמי | חובה לאנדרואיד |
| חשבון Expo (EAS) | חינם להתחלה | לבניית הקבצים בענן. `eas.json` כבר מוגדר עם שלושה פרופילים: development, preview, production |
| אייקון אפליקציה | - | 1024×1024, ללא שקיפות |
| מסכי צילום | - | לפי מידות החנויות |
| מדיניות פרטיות | - | חובה בשתי החנויות; אפשר להפנות לעמוד באתר |

התהליך עצמו:

```bash
npm install -g eas-cli
eas login
eas init                                             # מקשר את הפרויקט ל-EAS
# eas.json כבר קיים בריפוזיטורי - אין צורך ב-build:configure
eas build --platform ios --profile production        # בונה בענן
eas build --platform android --profile production
eas submit --platform ios --latest                   # מעלה ל-TestFlight
eas submit --platform android --latest
```

`eas init` **כותב `extra.eas.projectId` לתוך `app.json`** - זה שינוי בקובץ שצריך
לעשות לו commit. בלעדיו כל מחשב אחר ייצור פרויקט EAS חדש ונפרד.

### מה EAS ישאל בבנייה הראשונה ל-iOS

הבנייה הראשונה היא אינטראקטיבית, ולכן **חייבת לרוץ ממחשב** - וזו גם הסיבה
שהתיעוד של Expo דורש בנייה מוצלחת אחת ממחשב לפני שאפשר להפעיל בניות מגיטהאב.

| השאלה | התשובה |
|---|---|
| התחברות ל-Apple ID | החשבון עם הרשאות על החברה. יגיע קוד 2FA |
| ליצור Bundle ID `com.anshilo.shop`? | כן |
| שEAS ינהל Distribution Certificate ו-Provisioning Profile? | **כן.** זה מונע התעסקות ידנית בחתימות |
| ליצור רשומת אפליקציה ב-App Store Connect? | כן, אם עוד לא נוצרה |

**מספרי הבנייה מנוהלים אוטומטית:** `appVersionSource: "remote"` עם
`autoIncrement: true` ב-`eas.json`. אין מה לעדכן ידנית בין בניות.

### שני דברים שנפתרו מראש

**1. שאלת הצפנה בכל העלאה.** TestFlight שואל בכל העלאה על שימוש בהצפנה. האפליקציה
משתמשת רק ב-HTTPS של המערכת ובלי הצפנה עצמית, ולכן היא בפטור הסטנדרטי. הוגדר
`ITSAppUsesNonExemptEncryption: false` ב-`app.json`, **וזה מבטל את השאלה לתמיד**.

**2. האייקון תקין.** אפל דוחה אייקון עם שקיפות. ל-`assets/icon.png` יש ערוץ אלפא,
אבל נמדד: **0 מתוך 1,048,576 פיקסלים שקופים** - הוא אטום לחלוטין והכלל מתקיים.
אין מה לתקן. (ל-`splash-icon.png` יש שקיפות אמיתית ב-62% מהשטח, וזה נכון - הוא
יושב על רקע הנייבי.)

### ⚠️ החלטה שממתינה לפרסום בחנות

ב-`app.json` מוגדר **`supportsTablet: true`**. ל-TestFlight זה לא משנה, אבל
**בהגשה ל-App Store אפל תדרוש גם צילומי מסך לאייפד** ותבדוק את האפליקציה עליו.
אם לא מתכננים לתמוך באייפד - לכבות את זה לפני ההגשה.

**TestFlight פנימי לא עובר בדיקה של אפל.** אחרי עיבוד של דקות אפשר להתקין.
בדיקה חיצונית כן עוברת בדיקה. ההגשה לחנות עצמה לוקחת בדרך כלל 1-3 ימים באפל,
ובגוגל בין כמה שעות ליום.

> **טיפ:** אפל דוחה לפעמים אפליקציות חנות שהן "רק אתר בתוך מסגרת". האפליקציה
> הזאת אינה כזו - היא native ומשתמשת ב-API - אבל שווה להדגיש בתיאור את מה
> שייחודי לה: המועדפים, הזמנה מהירה לפי מקט, וההתקשרות והוואטסאפ בלחיצה.
