# הפעלת אפליקציית המובייל

האפליקציה בנויה ב-Expo (React Native) ומושכת את המוצרים, הקטגוריות, המלאי
והמחירים ישירות מהחנות דרך Shopify Storefront API. אין בסיס נתונים נפרד ואין
מה לתחזק — כל שינוי בחנות מופיע באפליקציה מיד.

התשלום מתבצע ב-Checkout של שופיפיי עצמו, כך שכל אמצעי התשלום שמוגדרים בחנות
עובדים גם באפליקציה.

---

## שלב 1 — הטוקן

> **כנראה שכבר עשיתם את זה.** בבדיקה מול ה-Admin API נמצא בחנות ערוץ מכירה
> בשם **"Shilo Mobile App"** על אפליקציית ה-**Headless** של שופיפיי, ו-1,867
> מוצרים כבר מפורסמים אליו — בדיוק כמו לחנות המקוונת. כלומר הערוץ קיים ומלא,
> והטוקן קיים; הוא פשוט לא הועתק לקוד.
>
> **איפה למצוא אותו:** ניהול החנות → **ערוצי מכירה → Headless** → הסטורפרונט
> **Shilo Mobile App** → **Storefront API** → מעתיקים את
> **public access token**. משם ישר לשלב 2.
>
> אם הערוץ נמחק או שאתם מתחילים מאפס — המשך השלב הזה מסביר איך יוצרים אותו.

זה החלק היחיד שחייב להיעשות בניהול החנות, וזה לוקח כשלוש דקות.

1. **הגדרות → אפליקציות וערוצי מכירה → פיתוח אפליקציות**
2. **יצירת אפליקציה** → שם: `Shilo Mobile App`
3. לשונית **Configuration** → בקטע **Storefront API** לוחצים **Configure**
4. מסמנים את ההרשאות:
   - `unauthenticated_read_product_listings`
   - `unauthenticated_read_product_inventory`
   - `unauthenticated_read_product_tags`
   - `unauthenticated_write_checkouts`
   - `unauthenticated_read_checkouts`
   - `unauthenticated_read_selling_plans`
5. **שמירה** → לשונית **API credentials** → **Install app**
6. מעתיקים את **Storefront API access token**

> הטוקן הזה נועד להיות ציבורי — הוא מיועד לצד הלקוח ולא מאפשר לקרוא הזמנות או
> נתוני לקוחות. אל תבלבלו אותו עם ה-Admin API token, שהוא סודי.

## שלב 2 — הזנת הטוקן

יש שתי דרכים. **הראשונה מומלצת** — היא מאפשרת להחליף טוקן בלי לגעת בקוד.

### דרך א' (מומלצת) — משתנה סביבה

לפיתוח מקומי, בתיקיית `mobile-app`:

```bash
cp .env.example .env
# פותחים את .env ומדביקים את הטוקן אחרי ה-=
```

`.env` לא נכנס ל-git, כך שהטוקן לא מסתובב בהיסטוריה.

לבנייה בענן (EAS), פעם אחת לכל סביבה:

```bash
eas env:create --name EXPO_PUBLIC_SHOPIFY_STOREFRONT_TOKEN --value <הטוקן> \
  --environment production --visibility plaintext
```

`eas.json` כבר מקשר כל פרופיל בנייה לסביבה המתאימה (`development` /
`preview` / `production`), כך שהבנייה מרימה את המשתנה לבד. חזרו על הפקודה עם
`--environment preview` אם אתם בונים גם פרופיל preview.

### דרך ב' — הדבקה בקוד

פותחים את `mobile-app/src/config.ts` ומחליפים את הערך של `TOKEN_INLINE`:

```ts
const TOKEN_INLINE = 'המקום-שבו-מדביקים-את-הטוקן';
```

משתנה הסביבה, אם הוגדר, גובר על הערך הזה.

> אם לא הוזן טוקן בכלל, האפליקציה לא תיראה סתם ריקה — היא תציג הודעה בעברית
> שמסבירה בדיוק מה חסר ואיפה להזין אותו.

הדומיין כבר מוגדר נכון:

```ts
storeDomain: '3007b3-4.myshopify.com',
```

זה הדומיין הפנימי של החנות בשופיפיי — **לא** `anshilo.com`. אין צורך לשנות אותו.

שאר הפרטים בקובץ (טלפון, וואטסאפ, כתובת, שעות) כבר מלאים בערכים האמיתיים, ומשם
הם מוזרמים לכל המסכים.

## שלב 3 — הרצה על הטלפון

```bash
cd mobile-app
npm install
npx expo start
```

מתקינים **Expo Go** מה-App Store או מ-Google Play, סורקים את ה-QR שמופיע
בטרמינל, והאפליקציה נפתחת על הטלפון. כל שינוי בקוד מתעדכן במסך תוך שנייה.

לבדיקה שהכל מתקמפל:

```bash
npx tsc --noEmit
```

### חשוב — Expo Go אינו מייצג את הבנייה האמיתית ב-RTL

זו הנקודה שהכשילה את הגרסה הקודמת ב-TestFlight, ולכן כדאי להכיר אותה.

כפיית ה-RTL מוגדרת ב-`app.json` דרך הפלאגין `expo-localization`, ו**פלאגיני
config אינם פועלים ב-Expo Go** — הם נכנסים לתוקף רק בבנייה אמיתית. התוצאה:

| סביבה | מתי RTL נדלק |
|---|---|
| Expo Go | רק אחרי טעינה מחדש (`r` בטרמינל). ההרצה הראשונה היא LTR |
| בנייה אמיתית (TestFlight / Play / `expo run:ios`) | מהפריים הראשון |

לכן אפליקציה שנבדקה רק בהרצה ראשונה ב-Expo Go נראית תקינה, ואותו קוד בדיוק
נראה אחרת ב-TestFlight. בהרצת פיתוח מופיעה אזהרה בקונסול כל עוד ה-RTL כבוי.

**איך בודקים נכון:** אחרי `npx expo start` לוחצים `r` לטעינה מחדש, ומאשרים
שהפריסה התהפכה — הטאבים מימין לשמאל, הטקסט צמוד לימין, חץ "כל המוצרים" מצביע
שמאלה. לבדיקה מלאה לפני העלאה לחנויות:

```bash
eas build --platform ios --profile preview
```

## מה יש באפליקציה

| מסך | מה בו |
|---|---|
| בית | חיפוש, רצועת מחלקות, מבצעים, נמכרים ביותר, חדש בקטלוג, מותגים |
| קטלוג | כל הקטגוריות עם מיון וטעינה אינסופית |
| קטגוריה | רשת מוצרים, מיון, טעינה בגלילה |
| מוצר | גלריה, בחירת וריאנט, מלאי, מחיר, הוספה לעגלה, שיתוף |
| חיפוש | חיפוש מוצרים מהיר |
| עגלה | מסונכרנת עם שופיפיי, נשמרת בין הפעלות, מעבר ל-Checkout |
| מועדפים | נשמרים על המכשיר |
| עוד | פרטי החנות, טלפון ווואטסאפ בלחיצה, שעות פעילות, מדיניות |

העיצוב זהה למערכת העיצוב של האתר — אותו אדום, אותו כחול־כהה, אותם כרטיסים —
כדי שהאתר והאפליקציה ירגישו כמו מוצר אחד.

## שלב 4 — העלאה ל-App Store ול-Google Play

זה שלב נפרד שדורש חשבונות מפתח בתשלום. מה שצריך:

| דרישה | עלות | הערות |
|---|---|---|
| Apple Developer Program | 99$ לשנה | חובה ל-iOS |
| Google Play Developer | 25$ חד־פעמי | חובה לאנדרואיד |
| חשבון Expo (EAS) | חינם להתחלה | לבניית הקבצים בענן. `eas.json` כבר מוגדר עם שלושה פרופילים: development, preview, production |
| אייקון אפליקציה | — | 1024×1024, ללא שקיפות |
| מסכי צילום | — | לפי מידות החנויות |
| מדיניות פרטיות | — | חובה בשתי החנויות; אפשר להפנות לעמוד באתר |

התהליך עצמו:

```bash
npm install -g eas-cli
eas login
# eas.json כבר קיים בריפוזיטורי — אין צורך ב-build:configure
eas build --platform ios --profile production        # בונה בענן
eas build --platform android --profile production
eas submit --platform ios --profile production       # שולח לבדיקה
eas submit --platform android --profile production
```

הבדיקה באפל לוקחת בדרך כלל 1–3 ימים, בגוגל בין כמה שעות ליום.

> **טיפ:** אפל דוחה לפעמים אפליקציות חנות שהן "רק אתר בתוך מסגרת". האפליקציה
> הזאת אינה כזו — היא native ומשתמשת ב-API — אבל שווה להדגיש בתיאור את מה
> שייחודי לה: המועדפים, הזמנה מהירה לפי מקט, וההתקשרות והוואטסאפ בלחיצה.
