מדריך העתק־הדבק, מההתחלה עד TestFlight.

## איך לקרוא את המדריך

כל שלב מסומן באחד משני סימנים:

| סימן | מה זה אומר |
|---|---|
| 🖥️ **טרמינל** | פקודה שאתם מריצים במחשב. **רק אתם** — סוכן דפדפן לא יכול להריץ פקודות |
| 🌐 **דפדפן** | עבודה באתר (שופיפיי / אפל / גוגל). אפשר לעשות ידנית, **או** להדביק את הפרומפט המצורף ל-Claude in Chrome ולתת לו לעשות |

**כלל אצבע:** אם השלב הוא 🖥️ — אין קסמים, צריך להעתיק פקודה. אם הוא 🌐 — יש

אם שלב נכשל — עוצרים שם ולא ממשיכים. השגיאה כמעט תמיד אומרת מה חסר.

## שלב 1 — להוריד את הקוד המתוקן

### 1א — קודם לעבור לתיקייה שלכם

**אל תדלגו על זה.** טרמינל בווינדוס נפתח לפעמים ב-`C:\Windows\System32`, שזו
תיקיית מערכת מוגנת, והורדה לשם נכשלת ב-`Permission denied`.

🖥️ **טרמינל:**

```bash
cd $HOME
```

עובד גם ב-PowerShell וגם ב-Mac. מעביר ל-`C:\Users\<שם>` (או `/Users/<שם>`),
שם יש הרשאות מלאות.

> אם הטרמינל נפתח ב-System32 — סימן שפתחתם אותו "כמנהל" (Administrator).
> לא צריך מנהל לשום דבר במדריך הזה.

### 1ב — להוריד

התיקונים יושבים בענף `claude/shopify-app-hebrew-compat-i1wcji`
([PR #3](https://github.com/A-N-Shilo/anshilo.com/pull/3)), **לא** בענף הראשי.

🖥️ **טרמינל:**

```bash
git clone -b claude/shopify-app-hebrew-compat-i1wcji https://github.com/A-N-Shilo/anshilo.com.git
cd anshilo.com/mobile-app
npm install
```

`npm install` לוקח 1–3 דקות. אזהרות (`warn`) זה בסדר, שגיאות (`error`) לא.

מכאן והלאה **כל פקודה רצה מתוך `mobile-app`**. אם פתחתם טרמינל חדש, לחזור:

```bash
cd $HOME/anshilo.com/mobile-app
```

## שלב 2 — הטוקן של החנות

**הטוקן כבר קיים אצלכם.** נבדק מול ה-API: יש בחנות ערוץ מכירה בשם
**"Shilo Mobile App"** על אפליקציית ה-Headless, עם 1,867 מוצרים מפורסמים אליו.
לא צריך ליצור כלום — רק להעתיק.

### 2א — למצוא ולהעתיק אותו

🌐 **דפדפן** — [**פרומפט 1**](#פרומפט-1--להביא-את-הטוקן-מהחנות) עושה את זה, או ידנית:

1. ניהול החנות → **ערוצי מכירה** (Sales channels)
2. **Headless**
3. הסטורפרונט **Shilo Mobile App**
4. **Storefront API**
5. להעתיק את **Public access token** ← ולא Private

### 2ב — להדביק אותו

הדרך הקצרה — בלי לפתוח עורך טקסט בכלל.

🖥️ **PowerShell** — **להחליף `הטוקן-שלכם`**, להשאיר את המרכאות:

```powershell
Set-Content -Path .env -Value "EXPO_PUBLIC_SHOPIFY_STOREFRONT_TOKEN=הטוקן-שלכם"
Get-Content .env
```

🖥️ **Mac / Linux:**

```bash
echo "EXPO_PUBLIC_SHOPIFY_STOREFRONT_TOKEN=הטוקן-שלכם" > .env
cat .env
```

השורה השנייה צריכה להחזיר את השורה שנכתבה, עם הטוקן. בלי רווחים סביב ה-`=`
ובלי מרכאות בתוך הקובץ.

`.env` לא נכנס ל-git — הטוקן לא ייחשף בריפוזיטורי.

## שלב 3 — לבדוק שהטוקן עובד

### ⛔ Expo Go לא עובד בפרויקט הזה — לא לנסות

נבדק בשטח ונכשל. **אין פתרון, וזו לא תקלה אצלכם:**

| | |
|---|---|
| הפרויקט | Expo **SDK 57** |
| Expo Go בחנות (iOS) | גרסה **54.0.2**, עודכן לפני ~10 חודשים |
| התוצאה | `Project is incompatible with this version of Expo Go` |

Expo Go 54 לא מריץ SDK 57, ואין גרסה חדשה יותר להוריד — בדף החנות מופיע
"פתיחה" ולא "עדכן". לכן **בדיקה על מכשיר מתרחשת רק בשלב 8, על בנייה אמיתית.**

זה גם לא הפסד: פלאגיני config לא פועלים ב-Expo Go, ולכן ה-RTL שם ממילא לא
מייצג. כל שיפוט של פריסה, אייקונים ויישור טקסט היה חייב לחכות לשלב 8 בכל מקרה.

### מה שכן בודקים כאן — שהטוקן תקין

Expo Go נדרש רק כדי לאמת את החיבור לחנות. אפשר לאמת אותו ישירות, מהיר ומדויק
יותר, בלי שום אפליקציה.

🖥️ **טרמינל** (PowerShell) — **להחליף `הטוקן-שלכם` בטוקן האמיתי**:

```powershell
$r = Invoke-RestMethod -Method Post -Uri "https://3007b3-4.myshopify.com/api/2025-07/graphql.json" -Headers @{ "X-Shopify-Storefront-Access-Token" = "הטוקן-שלכם" } -ContentType "application/json" -Body '{"query":"{ shop { name } products(first: 5) { nodes { title } } }"}'
$r.data.shop.name
$r.data.products.nodes.title
```

ב-Mac / Linux:

```bash
curl -s -X POST "https://3007b3-4.myshopify.com/api/2025-07/graphql.json" \
  -H "Content-Type: application/json" \
  -H "X-Shopify-Storefront-Access-Token: הטוקן-שלכם" \
  --data '{"query":"{ shop { name } products(first: 5) { nodes { title } } }"}'
```

**תקין =** שם החנות בעברית + חמישה שמות מוצרים אמיתיים מהקטלוג.

| מה חוזר | מה זה אומר |
|---|---|
| שם חנות + מוצרים | הטוקן תקין. ממשיכים לשלב 4 |
| `401` / `Unauthorized` | הטוקן שגוי — לחזור לשלב 2א ולהעתיק שוב |
| שם חנות אבל 0 מוצרים | הטוקן תקין, אבל חסרות הרשאות קריאת מוצרים בערוץ ה-Headless |
| שגיאת רשת / timeout | חסימת רשת מקומית — לנסות מרשת אחרת |

> זה מאמת את **הטוקן ואת החנות**. שהקובץ `.env` נטען נכון רואים בנפרד: אם
> הרצתם `npx expo start`, הוא הדפיס `env: load .env` בשורה הראשונה.

## שלב 4 — לחבר את הפרויקט ל-Expo

פעם אחת בלבד. 🖥️ **טרמינל:**

```bash
npm install -g eas-cli
eas login
eas init
```

`eas login` — המשתמש והסיסמה מ-expo.dev.
`eas init` — יוצר את הפרויקט בענן וכותב מזהה לתוך `app.json`. **זה הצעד שלא
נעשה קודם, ולכן הבנייה הקודמת לא יצאה מהריפו הזה.**

לשמור:

```bash
git add app.json
git commit -m "Link the EAS project"
git push
```

## שלב 6 — ⚠️ בדיקה אחת לפני הבנייה

ה-**Bundle ID** של האפליקציה הקיימת ב-App Store Connect חייב להיות בדיוק
`com.anshilo.shop`. אם לא — אפל תדחה את ההעלאה **אחרי** שחיכיתם 20 דקות לבנייה.

🌐 **דפדפן** — [**פרומפט 2**](#פרומפט-2--לבדוק-את-ה-bundle-id-באפל) בודק את זה, או ידנית:
App Store Connect → Apps → האפליקציה → General → App Information → Bundle ID.

- **זהה?** ממשיכים.
- **שונה?** לפתוח `mobile-app/app.json` ולהחליף את שני המקומות שכתוב בהם
  `com.anshilo.shop` (אחד תחת `ios`, אחד תחת `android`) ל-Bundle ID שלכם.

## שלב 7 — לבנות ולשלוח ל-TestFlight

🖥️ **טרמינל:**

```bash
eas build --platform ios --profile production
```

רץ בענן 10–25 דקות. אפשר לסגור את הטרמינל, הבנייה נמשכת.

בפעם הראשונה יישאלו שאלות על חתימה:

- **"Generate a new Apple Distribution Certificate?"** → **Yes**
- **"Generate a new Apple Provisioning Profile?"** → **Yes**
- יבקשו להתחבר עם ה-Apple ID שלכם → להזין

תנו ל-EAS לנהל את החתימות. זה מה שהוא טוב בו.

כשהסתיים:

```bash
eas submit --platform ios --profile production
```

אחרי 5–15 דקות עיבוד אצל אפל, הגרסה תופיע ב-TestFlight כ-**1.0.1**.

> הגרסה הועלתה מ-1.0.0 ל-1.0.1 בכוונה — אפל דוחה העלאה עם מספר גרסה שכבר קיים.

🌐 **דפדפן** — [**פרומפט 3**](#פרומפט-3--לעקוב-אחרי-העיבוד-בטestflight) עוקב אחרי
העיבוד ומודיע כשאפשר להתקין.

# פרומפטים ל-Claude in Chrome

איך משתמשים: פותחים את הלשונית הרלוונטית, מפעילים את Claude in Chrome, ומדביקים
את הפרומפט. כל פרומפט עומד בפני עצמו.

### לפני שמדביקים — שני כללים

1. **אל תיתנו לסוכן סיסמאות או קודי 2FA.** תתחברו לחשבון בעצמכם *לפני* שאתם
   מפעילים אותו. הוא עובד בתוך הלשונית המחוברת.
2. **בקונסולות של אפל וגוגל — קראו לפני שאתם מאשרים.** שם יש פעולות שמשפיעות על
   אפליקציה בפרודקשן. הפרומפטים למטה בנויים לקרוא ולדווח, לא לשנות, חוץ
   מפרומפט 4 שמעלה קובץ.

---

### פרומפט 1 — להביא את הטוקן מהחנות

> היכנס לאדמין של שופיפיי של החנות `anshilo.com` (הדומיין הפנימי:
> `3007b3-4.myshopify.com`) ומצא בשבילי טוקן Storefront API קיים.
>
> הנתיב: **Sales channels** (ערוצי מכירה) בתפריט הצד ← האפליקציה **Headless**
> ← הסטורפרונט בשם **Shilo Mobile App** ← הכרטיסייה **Storefront API**.
>
> שם מופיעים שני טוקנים. אני צריך את ה-**Public access token** בלבד.
> אם צריך ללחוץ "Reveal" או "Show" כדי לראות אותו — לחץ.
>
> החזר לי:
> 1. את ה-Public access token, כמחרוזת אחת מלאה בלי רווחים
> 2. אישור שהוא Public ולא Private
>
> חשוב:
> - **אל תיצור** סטורפרונט חדש, אל תיצור טוקן חדש ואל תעשה rotate/revoke לשום
>   טוקן קיים. קריאה בלבד.
> - **אל תיגע** ב-Admin API access token — הוא סודי ואני לא צריך אותו.
> - אם אין ערוץ Headless או אין סטורפרונט בשם הזה — עצור ותגיד לי מה כן יש,
>   בלי לנחש ובלי ליצור.

---

### פרומפט 2 — לבדוק את ה-Bundle ID באפל

> היכנס ל-App Store Connect (appstoreconnect.apple.com) ובדוק בשבילי פרט אחד.
>
> הנתיב: **Apps** ← האפליקציה של החנות "א.נ. שילו" (או שם דומה) ←
> **General** ← **App Information** ← השדה **Bundle ID**.
>
> החזר לי:
> 1. את ה-Bundle ID המדויק
> 2. האם הוא בדיוק `com.anshilo.shop` — כן או לא
> 3. את שם האפליקציה ואת מספר הגרסה האחרון שמופיע ב-TestFlight
>
> חשוב: **קריאה בלבד.** אל תשנה שדות, אל תיצור אפליקציה חדשה, אל תמחק בילדים
> ואל תשלח שום דבר ל-Review. אם יש כמה אפליקציות ואתה לא בטוח איזו — תאר לי
> את כולן ותן לי לבחור.

---

### פרומפט 3 — לעקוב אחרי העיבוד ב-TestFlight

> היכנס ל-App Store Connect (appstoreconnect.apple.com), לאפליקציה של
> "א.נ. שילו", לכרטיסייה **TestFlight**.
>
> אני מחפש בילד חדש בגרסה **1.0.1** שהעליתי הרגע. תגיד לי:
> 1. האם הוא מופיע ברשימה
> 2. מה הסטטוס שלו (Processing / Ready to Test / Invalid Binary / Missing
>    Compliance או אחר)
> 3. אם הסטטוס דורש פעולה — תסביר לי בדיוק איזו, אבל **אל תבצע אותה**
>
> אם הוא עדיין ב-Processing, רענן את הדף כל 2–3 דקות עד 20 דקות, ותעדכן אותי
> כשהסטטוס משתנה.
>
> חשוב: קריאה בלבד. אל תוסיף בודקים, אל תפיץ לקבוצות ואל תשלח ל-Review.
> אם מופיעה שאלת Export Compliance — תגיד לי מה היא שואלת ותן לי להחליט.

---

### פרומפט 4 — להעלות לגוגל Play

> היכנס ל-Google Play Console (play.google.com/console) והעלה קובץ שהורדתי.
>
> הקובץ נמצא בתיקיית ההורדות שלי, סיומת `.aab`, בשם שמכיל "anshilo" או
> "shilo". אם יש כמה — קח את החדש ביותר ותגיד לי איזה בחרת.
>
> הנתיב: האפליקציה של "א.נ. שילו" ← **Testing** ← **Internal testing** ←
> **Create new release** ← להעלות את ה-`.aab` לאזור ה-App bundles.
>
> אחרי ההעלאה:
> 1. תגיד לי איזה מספר גרסה (version code) נקלט
> 2. תגיד לי אם Google מציגה אזהרות או שגיאות, ומה הן
> 3. **עצור שם.** אל תלחץ Review release ואל תלחץ Start rollout — אני רוצה
>    לראות לפני שזה יוצא לבודקים
>
> חשוב: אל תיגע בשום דבר ב-**Production**. רק Internal testing.

### פרומפט 5 (אופציונלי) — ליישר את סימן השקל בין האתר לאפליקציה

האפליקציה מציגה `₪149.00` והאתר מציג `149.00 ש"ח`, כי כך מוגדר בחנות. הפרומפט
הזה מיישר את האתר לאפליקציה. **זה שינוי באתר החי** — רק אם אתם רוצים את זה.

> היכנס לאדמין של שופיפיי של `anshilo.com` ושנה את פורמט המטבע.
>
> הנתיב: **Settings** (הגדרות) ← **General** (כללי) ← החלק
> **Store currency** / **Currency formatting** (פורמט מטבע).
>
> יש שם שני שדות. כרגע שניהם מכילים `{{amount}} ש"ח`.
> תשנה את שניהם ל-`₪{{amount}}` — כלומר סימן השקל **לפני** הסכום, בלי רווח.
>
> לפני שאתה שומר: הראה לי צילום מסך של שני השדות אחרי השינוי ותן לי לאשר.
> אחרי השמירה: תגיד לי שהשמירה הצליחה.
>
> חשוב: אל תיגע במטבע עצמו (צריך להישאר ILS / שקל), ואל תשנה שום הגדרה אחרת
> בעמוד הזה.

**אחרי שמריצים את פרומפט 5** צריך לעדכן גם את האפליקציה כדי שתישאר מיושרת —
תגידו לי ואני אעשה את זה בקוד.

## תקלות נפוצות

| השגיאה | הפתרון |
|---|---|
| `Permission denied` בהורדה | לא הרצתם `cd $HOME` — שלב 1א |
| `command not found: eas` | להריץ שוב `npm install -g eas-cli` |
| `eas.json is not valid` / שדה לא מוכר | ה-eas-cli ישן. `npm install -g eas-cli@latest` |
| "האפליקציה עדיין לא חוברה לחנות" | הטוקן. שלב 2 (מקומי) או שלב 5 (בענן) |
| מסך ריק בלי הודעה | הטוקן תקין אבל חסרות הרשאות — לבדוק בערוץ ה-Headless שמסומנות הרשאות קריאת מוצרים |
| אפל: `build number already used` | להעלות `version` ב-`app.json` (למשל 1.0.2) ולבנות שוב |
| `Project is incompatible with this version of Expo Go` | צפוי — Expo Go לא תומך ב-SDK 57. ראו שלב 3, אין מה לתקן |
| הפריסה LTR בבנייה אמיתית | לא צפוי. לצלם ולדווח — הכפייה מוגדרת ב-`app.json` |
| `Invalid bundle identifier` | שלב 6 — ה-Bundle ID לא תואם |

## סיכום — כל הפקודות ברצף

```bash
# פעם אחת
cd $HOME
git clone -b claude/shopify-app-hebrew-compat-i1wcji https://github.com/A-N-Shilo/anshilo.com.git
cd anshilo.com/mobile-app
npm install
cp .env.example .env          # ← להדביק את הטוקן בקובץ
npm install -g eas-cli
eas login
eas init

# כל בנייה מכאן והלאה
eas build --platform ios --profile production
eas submit --platform ios --profile production
```
