שני דברים שדורשים התחברות לחשבונות שלכם ולכן לא יכולים להיעשות מכאן.
כל פרומפט עומד בפני עצמו — להעתיק, להדביק, ולתת לסוכן לעבוד.

**כלל אחד לפני שמתחילים:** אם סוכן מבקש להדביק סיסמה או קוד דו-שלבי — תעשו
את זה אתם, ידנית. אל תכתבו סיסמאות בצ'אט.

> ⚠️ **הדפוס של "סוכן קורא, בן אדם מעביר" הוא עצמו נזילה. תכננו סביבו.**
>
> הסוכן כאן התנהג נכון: הוא סירב לחשוף את ה-client secret והסביר למה.
> הסוד בכל זאת הגיע לתמליל, כי הבעלים העתיק אותו ידנית מהמסך אל הצ'אט כדי
> להעביר אותו הלאה. אף אחד לא עשה משהו שגוי בכוונה — הדפוס עצמו הוא הבעיה.
>
> **הכלל: סוד לא צריך לנוע.** הוא נקרא מהמסך ונכתב ישר ל-`.env`, בלי לעבור
> דרך שום צ'אט — לא של סוכן ולא של קלאוד. אם סוד כבר עבר בתמליל, הוא חשוף,
> וזה לא תלוי במי הדביק אותו.
>
> מה שהגביל כאן את הנזק היא ההפרדה שנעשתה סעיף אחד קודם: לאפליקציה הזאת יש
> `write_products` ו-`write_files` בלבד, ולכן החשיפה נוגעת במוצרים ובקבצים —
> ולא בלקוחות, לא בהזמנות ולא בטוקן הקטלוג. אם ההרשאות היו נוספות ל-Shilo
> Mobile App כפי שההוראה המקורית שלי הציעה, אותה נזילה הייתה שורפת גם את
> טוקן ה-Storefront שהאפליקציה והאתר תלויים בו.

## פרומפט 2 — חשבון שירות ל-`eas submit`  ⛔ **לא עושים את זה. נבדק ונדחה.**

**המסקנה מהסבב שבו זה נוסה: אין בזה צורך, והמחיר שלו גבוה מהתועלת.**

שלוש עובדות שהתגלו בשטח, ושסותרות את ההנחות שהפרומפט המקורי נשען עליהן:

1. **גוגל דורשת שההעלאה הראשונה של AAB לאפליקציה חדשה תיעשה ידנית**
   ב-Play Console, לפני שה-API רשאי להעלות גרסאות בכלל. כלומר חשבון שירות
   לא מקצר כלום בדרך להגשה הראשונה — הוא רק חוסך העלאות **בגרסאות הבאות**.
2. **יצירת מפתחות JSON חסומה במדיניות ארגונית** —
   `iam.managed.disableServiceAccountKeyCreation`, אכופה על ארגון
   `anshilo.com`. **אל תחרגו ממנה.** זו בקרת אבטחה שגוגל עצמה ממליצה עליה:
   מפתח JSON של חשבון שירות הוא סוד נייד שאינו פג ושאפשר להעתיק. לחרוג
   ממנה ברמת הארגון כדי לחסוך העלאה ידנית הוא יחס גרוע בין תועלת לסיכון.
3. **הדף `Setup → API access` לא קיים יותר** ב-Play Console. גישה לחשבון
   שירות ניתנת דרך *משתמשים והרשאות*.

חשבון השירות `eas-play-publisher@anshilo-shopify-login.iam.gserviceaccount.com`
כבר נוצר ואין לו הרשאות. הוא לא מזיק — אפשר להשאיר אותו.

**אם בעוד כמה גרסאות תרצו אוטומציה**, המסלול הנכון הוא חריגה **לפרויקט
הבודד** `anshilo-shopify-login` ולא לארגון, ואז גם להפעיל את
`Google Play Android Developer API` באותו פרויקט. לא לפני שיש צורך אמיתי.

עד אז: **להעלות את ה-AAB ידנית.** `eas.json` נשאר בלי
`serviceAccountKeyPath`, ו-`eas submit --platform android` פשוט לא בשימוש.

## פרומפט 2 (מקורי, נשמר להיסטוריה) — Google Cloud: חשבון שירות

> אני צריך חשבון שירות של Google שיאפשר ל-EAS להעלות אוטומטית ל-Google Play.
> אני מחובר לשני החשבונות. תעבוד שלב-שלב:
>
> 1. ב-**Google Play Console** → Setup → **API access**. אם עוד לא מקושר
>    פרויקט Google Cloud — תקשר או תיצור אחד.
> 2. ב-**Google Cloud Console** → IAM & Admin → **Service Accounts** →
>    Create service account. שם: `eas-play-publisher`.
> 3. אחרי היצירה → Keys → **Add key** → **Create new key** → **JSON**.
>    הקובץ יורד למחשב. **תגיד לי איפה הוא נשמר ואל תפתח את התוכן שלו בצ'אט.**
> 4. חזרה ל-**Play Console** → API access → תמצא את חשבון השירות החדש →
>    **Grant access**. הרשאות מינימליות שצריך:
>    - Releases: **Release to testing tracks**
>    - Releases: **Release apps to production** (רק אם תרצו הגשה אוטומטית
>      גם ל-production; אחרת לא חובה)
>    - App access: האפליקציה `com.anshilo.shop`
> 5. תאשר את ההזמנה ותוודא שהחשבון מופיע כ-Active.
>
> כשתסיים תגיד לי את הנתיב לקובץ ה-JSON ואת כתובת האימייל של חשבון השירות.

**אחרי שיש קובץ JSON**, מה שנשאר זה שורה אחת ב-`mobile-app/eas.json`, תחת
`submit.production.android`:

```json
"serviceAccountKeyPath": "../play-service-account.json"
```

ולהוסיף את שם הקובץ ל-`.gitignore`. **הקובץ הזה סודי** — הוא מרשה העלאת
גרסאות בשמכם. אל תעלו אותו ל-git ואל תדביקו את תוכנו בצ'אט.

## פרומפט 3 — Shopify: טוקן Admin API להלבנת התמונות

זה מה שחסר כדי להריץ `--apply` על 50 התמונות עם הרקע הצבעוני.

> אני צריך טוקן Admin API לחנות שופיפיי שלי, עם שתי הרשאות בלבד. אני מחובר
> לאדמין של `anshilo.com`. תעבוד שלב-שלב:
>
> 1. Settings → **Apps and sales channels** → **Develop apps**.
> 2. אם יש שם אפליקציה בשם **Shilo Mobile App** — תשתמש בה. אם לא —
>    **Create an app**, שם: `Shilo Image Tools`.
> 3. בתוך האפליקציה → **Configuration** → **Admin API integration** →
>    Configure.
> 4. תסמן **בדיוק** את שתי ההרשאות האלה ולא יותר:
>    - `write_products`
>    - `write_files`
> 5. Save.
> 6. **API credentials** → **Install app** → ואז **Reveal token once**.
>
> הטוקן מתחיל ב-`shpat_`. **אל תדביק אותו בצ'אט ואל תשלח לי אותו.** תגיד לי
> רק שהוא מוכן, ואני אעתיק אותו בעצמי מהמסך.

**איפה לשים אותו:** בקובץ `mobile-app/.env`, שורה חדשה:

```
SHOPIFY_ADMIN_TOKEN=shpat_...
```

`.env` כבר ב-`.gitignore`, אז הוא לא יעלה ל-git. **הטוקן הזה סודי** — הוא
מרשה שינוי מוצרים וקבצים בחנות. הוא שונה לגמרי מטוקן ה-Storefront, שהוא
ציבורי מתוקף תפקידו.

אחרי שהוא במקום, הרצה יבשה כדי לוודא שהוא נקרא, ואז ההחלה:

```bash
cd mobile-app
node scripts/whiten-product-images.js                       # יבש, לא נוגע בחנות
node scripts/whiten-product-images.js --apply --vendor "חגית"   # רק הסולמות
node scripts/whiten-product-images.js --apply                  # כל ה-50
```

**מומלץ להתחיל ב-`--vendor "חגית"`** — 32 התמונות שם הן הרקע הנייבי
האמיתי, החד-משמעי. אחרי שרואים שהתוצאה בחנות טובה, להריץ על השאר.
